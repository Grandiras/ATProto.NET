# Conformance vectors

Every file under `vectors/` with its provenance: where it comes from, at which commit or
version, under which licence, and how to regenerate it. Each area's files live in their own
folder; a folder's `README.md`, where present, has the details. Vectors are data: do not edit
them by hand, regenerate them.

A vector's ID is `{file}#{case}`, the case being the line, the fixture's own name or its index.
`IProtocolAdapter.KnownFailures` refers to vectors by these IDs.

Each file is `{"source", "cases": [...]}`; a case is `{case, nsid, params, clientProxy?, request, response, expect}`:

- `params` is what a caller passes, by Lexicon name: a query's parameters, a procedure's input object (arrays are
  arrays, `uri` stands for a record read or deleted by AT URI, a blob input is `{"$bytes": base64}` plus `mimeType`).
  For a query it is the expected query string read back, so the adapter maps it onto its own API.
- `request` is what must reach the wire: `method`, `query` (ordered, unescaped pairs; a repeated key is repeated,
  declaration order as 0.8 sent it), `body` (compared as JSON, property order free; absent means the original
  test did not assert it: three procedures), `bodyBase64`, `contentType`, `headers` (`atproto-proxy` is
  asserted absent unless listed), `rawQuery` (the percent-encoded form, when that is the point) and
  `typeFirst` (body objects that must write exactly one `$type`, first).
- `response` is the scripted reply (`status`, `contentType`, `headers`, and one of `body`, `text`, `base64`).
- `expect` is `outputIsResponse` (the decoded output holds everything the response body has) or `output`
  (a subset), `binary`, or `error` (`name`, `status`, `message`); neither means the call must just succeed.
  Output is compared as Lexicon JSON, as a subset: extra properties an SDK adds (a `$type`, defaults) are fine.

A vector's ID is `xrpc/{file}#{case}`.
